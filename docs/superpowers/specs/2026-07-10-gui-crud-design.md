# 通途图形客户端优化设计:CRUD 补全、完整 URL 显示、协议自动探测

日期:2026-07-10
状态:已确认(用户批准)

## 背景

用户实测中暴露三类问题:

1. 应用「本地服务协议」选错(本地 8000 是普通 HTTP 却选了 https),cloudflared 对明文服务发起 TLS 握手,公网访问 502(`tls: first record does not look like a TLS handshake`)。用户期望:**不管本地服务是 HTTP 还是 HTTPS,公网侧都以 HTTPS 提供访问,用户无需关心协议**。
2. 域名管理缺「修改」能力(唯一有意义的修改是换绑凭证);应用删除按钮存在但可见性不足,且原生 `confirm()` 在部分浏览器环境可能被拦截。
3. 概览/应用页的公网地址只显示主机名,未显示完整 URL。

## 设计决策

### ① 协议自动探测(核心)

- 应用的 `proto` 请求值新增 `auto`(前端默认选中「自动检测」)。
- 后端在创建/更新应用且 `proto == "auto"` 时,对 `local` 地址做快速探测(总预算 ≤2s):
  1. `net.DialTimeout("tcp", local, 1s)` 失败 → 本地服务未启动:按 `http` 保存,响应带 `warning` 字段提示"本地服务未启动,已按 http 配置,可稍后编辑"。
  2. TCP 可达 → `tls.DialWithDialer`(1.5s,`InsecureSkipVerify`)握手成功 → `https`;失败 → `http`。
- 配置文件仍只存 `http/https/tcp` 具体值,无 schema 变更;探测发生在保存时,不在运行时。
- 高级选项保留手动指定 http/https/tcp;`tcp` 只能手动选择(无法探测语义)。
- 向导第三步不出现协议概念(内部用 auto)。
- 舍弃的备选:仅改文案(防不住不读提示的用户)、运行时报警(改动大、收益边际,YAGNI)。

### ② 域名「修改」= 换绑凭证

- 新增 `PUT /api/domains/{name}`,请求体 `{"cred": "别名"}`:用新凭证调 `FindZone` 重新验证该域名可见性,成功则更新 `cred`、`zone_id`、`account_id`。
- UI:域名行加「换绑凭证」按钮 → 弹窗内凭证下拉 + 确认。
- 凭证管理(新增/更新 Token/删除)已齐备,不改。域名改名无意义(等价删除重建),不做。

### ③ 删除体验统一(应用/域名/凭证)

- 原生 `confirm()` 全部替换为**页面内确认弹窗**:红色危险样式,明确写出后果(应用删除注明"将同时删除 Cloudflare 上的 DNS 记录")。
- 应用删除弹窗内提供「保留 Cloudflare DNS 记录」勾选(对应 API `?keep_dns=1`、CLI `--keep-dns`)。
- 操作按钮列加大间距/字重,提高可见性。

### ④ 公网地址显示完整 URL

- 概览与应用页:`https://` + hostname,可点击新窗口打开。
- `tcp` 应用:显示主机名 + `TCP` 标签,不带链接(浏览器无法直接访问)。

### ⑤ 现存 502 的修复路径

实现后用户操作:应用页 → 编辑 test → 协议「自动检测」→ 保存 → 探测出 8000 为 HTTP 并自动纠正。

## API 契约变化

| 端点 | 变化 |
|---|---|
| `POST /api/apps` / `PUT /api/apps/{name}` | `proto` 接受 `auto`;响应可含 `warning` 字符串 |
| `PUT /api/domains/{name}` | 新增:`{"cred":"别名"}`,重验 Zone 后换绑 |

## 错误处理

- 探测超时短(1s + 1.5s),保存操作最坏多等 ~2s;探测仅在 `auto` 时发生。
- 换绑凭证时新凭证看不到该 Zone → 400,携带 CF 原始错误信息。
- 确认弹窗为纯前端组件,无并发/状态问题。

## 验证标准

- `go vet` + 构建通过。
- 预览浏览器实测:auto 探测(HTTP 服务→http;不可达→警告+http)、域名换绑、三类删除弹窗(应用含保留 DNS 勾选)、完整 URL 显示与链接、tcp 应用无链接。
